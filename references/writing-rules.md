# 受控中文写作规则全集

本文件是 `SKILL.md` 的参考层：规则展开、中文特有的坑、与上游 ASD-STE100 的对应关系、linter 规则名表、引用。
它**不复述** ASD-STE100 的正文，也不提供任何「受控词表」—— 中文没有这样的官方标准，本技能给的是规则与方向。

## 一、上游是什么

ASD-STE100 是受控自然语言，1986 年由现在的 ASD（欧洲航空航天与国防工业协会）发布，起因是欧洲航空公司
需要「不会被读错的」英文维修手册 —— 读错一条指令会死人。标准由 STEMG 维护，Issue 6（2013）起免费获取，
当前版本 Issue 9（2025 年 1 月）。结构是：**9 节 53 条写作规则** + 约 900 个受控词（每个词只有一个意思、
一种词性）与约 1200 个需替换的词 + 允许组织自建术语表。

## 二、上游规则类别 → 中文对应

| 上游类别 | 上游要求 | 中文对应做法 |
|---|---|---|
| 词义 | 一词一义，只用受控词义 | 一词一义靠**全篇一致**：同一概念只用一个词，不靠上下文区分 |
| 词形 | 一个词只有一种词性 | 优先名词或动词中更直白的那个；不在同一段里让同一个词换词性 |
| 动词 | 动作用动词，不用动词派生名词（Rule 3.7） | 禁「进行 / 作出 / 加以 / 予以 / 给予 / 开展 + 动作名词」；直接写动词 |
| 短语动词 | 禁止动词 + 介词（Rule 9.3） | 中文对应：禁用「做一下处理」「搞一下优化」这类「动词 + 一下 + 名词」的含糊搭配 |
| 时态 | 只允许不定式、祈使、一般现在 / 过去 / 将来、过去分词作形容词；禁完成时 | 中文体貌从简：「已经……了 / 正在……中 / ……过」只在**当前相关性**是信息时保留，并在输出里标注 |
| 语态 | 程序与指令必须主动；被动只在施事未知或无关时（描述文） | 同。中文的被动检查点是「被」字句与「由……所」结构 |
| 句长 | 程序 ≤ 20 词，描述 ≤ 25 词 | 汉字按「字」算：指令 ≤ 25 字，说明 ≤ 40 字（linter 默认 40，程序步骤用 `--max-chars 25`） |
| 一句一动作 | 一句话只给一个指令 | 同。中文最常见的违反形式是分号、「并且 / 同时 / 从而」串联 |
| 不省略 | 主语、动词、冠词不能为省字而删 | 中文对应：不省主语、不省量词与范围限定（「文件未备份将丢失」→「未备份的文件会丢失」） |
| 名词簇 | 名词堆叠 ≤ 3 个词 | 中文对应：定语连缀 ≤ 3 层（「高压燃油泵进口阀门总成」拆开） |
| 标点 | 分号一律不许（Rule 8.1），其余标准标点可用 | 同：不用分号连接动作；破折号连接通常说明这句该拆 |
| 段落 | 一段一主题，≤ 6 句；≥ 3 步或 ≥ 3 个条件用列表 | 同 |
| 安全 | 安全指令以明确的命令或条件开头 | 同。中文对应：不要用「建议注意」「请留意」这类软表述替代命令 |

## 三、中文特有的坑（上游没有，本技能新加）

上游是从英语的失败模式里长出来的。中文技术文本的失败模式有相当一部分不重合，下面六条是本技能的增量：

1. **虚动词**（进行 / 加以 / 作出 / 予以 / 开展 + 动作名词）。中文独有，英文对应物是 nominalization。
   它同时做三件坏事：句子变长、施事被藏起来、动作被抽象成名词。
2. **套话**（需要注意的是、值得一提的是、在一定程度上、某种意义上、综上所述、不难看出）。
   删掉之后信息量不变，属于纯噪声。
3. **营销形容词**（无缝、强大、赋能、闭环、极致、丝滑、一站式、颠覆、领先）。
   标准做法是换成可测量的说法，或者删掉这一句。
4. **同义轮换**。中文同义词特别多（检查 / 校验 / 核对 / 核查），模型为了「语言丰富」会轮着用；
   读者无法判断它们是同一个动作还是四个动作。
5. **含糊限定**（若干、一些、相关、有关、适当、酌情、必要时）。中文技术写作里这类词极易被当成
   「万能修饰」；要么给数量与范围，要么删。
6. **翻译腔**（基于……的情况下、对于……而言、这是一个……的事实、不仅……而且……而且）。
   多半是英文长句直译留下的结构，删掉外壳后主语和动作反而清楚了。

## 四、情态是内容

所有规则里最容易出错的是这一条：**「可能 / 也许 / 大概 / 有时 / 倾向于」承载作者的置信度，置信度是内容。**
把「请求可能已失败」改成「请求失败」不是简化，是换了结论；把「可能是 X 导致的」改成「X 是原因」同理。
linter 因此**永不标记情态**，`--selftest` 里有一条断言：「请求可能已失败。」必须干净。

例外是复合体貌：当「已经……了」表达的是**当前相关性**（「任务已完成，结果可以直接读」）而不是历史时，
保留它并标注这处偏离；纯粹的历史陈述可以简化。

## 五、linter 规则名表

| 规则名 | 严重度 | 查什么 |
|---|---|---|
| `semicolon` | 硬 | 分号把两件事串进一句 |
| `long-sentence` | 硬 | 句长超过 `--max-chars`（默认 40 字） |
| `nominalization` | 硬 | 虚动词 + 动作名词 |
| `marketing-adjective` | 硬 | 营销形容词表命中 |
| `empty-phrase` | 硬 | 套话表命中 |
| `synonym-rotation` | 硬 | 同义组内两个以上成员在同一文件出现 |
| `passive-voice` | 建议 | 「被」字句 |
| `compound-aspect` | 建议 | 已经……了 / 正在……中 |
| `vague-word` | 建议 | 若干、一些、相关、适当、必要时…… |
| `halfwidth-punct` | 建议 | 中文句中的半角标点 |
| `dash-join` | 建议 | 破折号连接 |

硬违规总数超过 `--baseline`（默认 0）时退出码 1；建议类只报告。`--json` 出结构化结果，
`--list-rules` 列出全部，`--disable 名,名` 关掉指定规则。

口径说明：linter 只做**机械首查**。它不比较原文与改写、不判断情态强度有没有变、不证明原意被保留。
零违规只说明配置的这几项机械检查没发现问题。
